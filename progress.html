# Implementation Plan This project is the new from-scratch PHP-to-native compiler line described in `NEW_PROMPT.md`. The plan is to grow one generic compiler/runtime architecture that can plausibly reach broad PHP compatibility, not to accumulate exact-output patches for individual PHPT rows. ## Operating Rules - Use CAO for supervised developer lanes; do not use the legacy harness workflow, legacy impl-agent panes, or non-CAO worker automation. - Do not use remote tunnels or expose the local network. - A task is ready only after it is integrated into the active branch, tested, documented, committed, and pushed. - Keep `PROGRESS.md` current in the remote repository after each meaningful behavior change. - Prefer small integrated batches over large unmerged inventory. - Never stop the whole production line on one failing integration. Contain the defect, split the work, preserve evidence, and keep independent slices moving. - Do not claim support until executable code and tests prove it through generic semantics. - Use stable Rust unless a documented technical reason requires otherwise. - Use `tools/checkpoint.sh` for checkpoint commits. ## Production System Use continuous integration in the production-system sense: short feedback loops, visible defects, small batches, and constant integration into the active branch. The default cycle is: 1. Choose one generic semantic capability. 2. Implement the smallest native-exercised vertical slice. 3. Add unit tests and at least one CLI/native binary proof. 4. Update docs and `PROGRESS.md`. 5. Run `tools/checkpoint.sh`. 6. Push only after the checkpoint commit succeeds and the remote update is a fast-forward. 7. Start the next slice. Defects should create containment, not paralysis: - If a slice fails late, either reduce it to the passing core or park it in a clearly named branch/patch with exact failing evidence. - If docs/tests expose unsupported behavior, name it instead of hiding it. - If a feature grows too large, split at runtime boundaries, not at test-output shapes. ## Architecture Target The compiler should keep these layers distinct: 1. Lexer and parser with source spans. 2. AST that preserves PHP syntax structure and diagnostic locations. 3. Semantic model for scopes, symbols, functions, classes, namespaces, and dynamic uncertainty. 4. Runtime model with boxed PHP values. 5. PHP-aware IR that preserves evaluation order and future reference behavior. 6. Native backend that emits code calling the shared runtime. 7. Explicit dynamic fallback zones for `eval`, variable variables, runtime symbol mutation, and similarly hard dynamic behavior. 8. PHPT/differential testing as compatibility signals, not implementation templates. The runtime must grow toward PHP-shaped values: boxed values first, then ordered arrays, references, copy-on-write, object metadata, exceptions, resources, and extension APIs. ## Current Baseline Integrated baseline: - Rust crate `ptn`. - CLI: `ptn compile <input.php> -o <native-binary> [--emit-c]`. - Source is lexed and parsed into AST with spans. - AST lowers to PHP-aware IR. - C backend emits a boxed-value runtime and compiles a native executable. - Supported literals: strings, integers, floats, booleans, and null. - Supported statements: `echo` and direct named-variable assignment. - Direct named-variable reads and overwrites use a generated C `PtnSymbolTable` storing boxed `PtnValue` slots by name. Known unsupported areas: - Arrays, functions, classes, includes, references, copy-on-write, resources, exceptions, diagnostics parity, and dynamic fallback remain unimplemented. - Variable variables and runtime symbol-table mutation are explicit dynamic fallback zones. - Undefined-variable warning parity is not implemented yet. ## Immediate Next Slice Add boxed expression operations as shared runtime helpers, not compile-time folding: - Lexer/parser/AST: binary expressions for arithmetic, concatenation, comparison, and boolean operations in a small precedence-aware expression parser. - IR: value-expression operation nodes that preserve left-to-right evaluation. - Runtime/backend: helper calls over `PtnValue` such as numeric addition and string concatenation, with room for PHP conversion diagnostics. - Native proof: compile and run programs such as: ```php <?php $name = "Ada"; echo "Hello " . $name . "\n"; $total = 2 + 3; echo $total, "\n"; ``` Unsupported edges to name: - Full PHP numeric-string conversion parity. - Overflow and warning diagnostics. - References and copy-on-write behavior. - Arrays and object conversions. Ready criteria: - `cargo fmt --check` - `cargo test` - Manual CLI native compile/run proof. - README/architecture/progress updates. - Checkpoint commit and fast-forward push to the default branch. ## Milestones ### Milestone 1: Core Statements and Values - Variables and assignment through runtime symbols. - Arithmetic, concatenation, comparison, and boolean operations through runtime helper functions. - `if`, `while`, `for`, `foreach` skeletons in IR with native codegen. - PHP conversion rules for echo, truthiness, numeric conversion, and string conversion. - Differential tests against PHP for broad expression families. ### Milestone 2: Arrays - Implement PHP ordered maps with integer/string key canonicalization. - Support array literals, reads, writes, append, unset, count, and iteration. - Preserve insertion order and PHP key conversion behavior. - Add native tests and differential tests for array families. ### Milestone 3: Functions and Calls - Function declarations and call table. - Arguments, defaults, variadics, named arguments, return values. - By-value call semantics first, then by-reference parameters. - Internal function registry with shared argument parsing and diagnostics. ### Milestone 4: References and Copy-On-Write - Represent reference identity explicitly in runtime values. - Add copy-on-write containers for strings/arrays where needed. - Support assignment/reference interactions and mutation visibility. - Add focused tests before expanding PHPT coverage. ### Milestone 5: Diagnostics, Errors, and Exceptions - Runtime error channel for warnings, notices, fatal errors, and recoverable diagnostics. - Exceptions, stack traces, `try`/`catch`/`finally`, and destructor timing. - Source-location propagation from AST through IR into runtime calls. ### Milestone 6: Objects and Classes - Class metadata, object storage, properties, methods, visibility, inheritance, interfaces, traits, static members, constants, and late static binding. - Magic methods and reflection metadata. - Constructor/destructor behavior. ### Milestone 7: Files, Includes, and Program Model - Multiple input files. - `include`, `require`, `*_once`, path resolution, and compile-unit tracking. - Globals, superglobals, constants, and namespace resolution. ### Milestone 8: Standard Library and Extensions - Build an internal-function module system. - Prioritize functions that unlock broad PHPT clusters. - Share common argument coercion, resource handling, errors, and reflection metadata. ### Milestone 9: Compatibility Scaling - Add PHPT discovery/reporting without reviving the old harness workflow. - Track pass/fail counts, regressions, unsupported clusters, and fallback usage. - Fix semantic clusters, not isolated expected-output rows. ### Milestone 10: Backend Hardening - Keep the C backend as a stable native path while runtime semantics mature. - Add lower-level native backend work only after runtime contracts are stable. - Add optimization guarded by runtime checks and fallback/deopt paths. ## Testing Strategy Testing must prove generic behavior: - Unit tests for lexer, parser, IR, and runtime helper contracts. - Integration tests that compile PHP to native binaries and execute them. - Differential tests against PHP for semantic families. - PHPT runs as compatibility telemetry once the compiler can exercise meaningful subsets. - Regression tests for every fixed semantic bug. Tests must not hard-code test filenames, PHPT row identities, or one-off output strings as implementation conditions. ## Progress Metrics Track these in `PROGRESS.md`: - Native-compiled language features that are implemented and tested. - Number of Rust tests and native binary integration tests. - Differential behavior families covered. - PHPT subset pass/fail counts when available. - Known unsupported edges and fallback zones. - Latest pushed commit for integrated progress. The primary metric is integrated native-compatible semantic coverage, not local patch inventory. ## Branch and Remote Discipline - The old compiler line is archived in the remote branch `archive/pre-scratch-20260608T235148Z`. - The active scratch line lives in `~/ptn-from-scratch` and pushes to the remote default branch. - Push often after integrated, tested slices. - Keep unpushed work small and visible.
