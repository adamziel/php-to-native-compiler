Implemented:

  • Consolidated the dynamic-holder copied-source overwrite hooks behind a

    • shared holder-storage mutation boundary. Object-property and alias-root write sites now delegate pre-replace rehydration and post-replace invalidation through one boundary object carrying the resolved holder identity and selected child path, instead of matching each spelling with a separate predicate. Runtime-cell source matching for these replacements now uses the resolved lvalue handle/reference-cell identity captured by that boundary, and the same pre-mutation boundary instance is reused for post-replace invalidation so root rebinding cannot hide the copied source. Direct property boundaries now capture that identity through the same runtime lvalue-handle resolver used by alias-root boundaries, including visible non-public context roots, instead of using a separate direct object-property reference-cell matcher. The older object-property-specific rehydrate/invalidate wrappers were removed; direct object-property writes and alias-root writes now enter the shared pre_replace_holder_storage() / post_replace_holder_storage() API with a resolved boundary. Focused runtime_cell_copy_source unit coverage remains green. A follow-up audit also routed the object-property result/output helper stores used by mysqli_stmt_fetch() result bindings, headers_sent() output parameters, and direct object-property ksort() / next() mutation writeback through the same boundary, and reference-cell promotion now runs post-replace invalidation only after the replacement bind succeeds while still reusing the pre-replace captured identity. The direct object-property next() writeback uses the selected nested offset path for its boundary instead of widening to the whole property. The rehydration half now consumes the captured boundary directly instead of reconstructing source identity from object/property names, so non-public context roots keep their runtime-cell identity through pre-replace materialization. The direct ArrayCopySourceRoot::ObjectProperty reference-return promotion fallback also routes whole-property and nested source promotion writes through the same pre/post boundary. This is a consolidation of the existing assignment, compound assignment, unset, ??=, reference assignment, alias-write, reference-promotion, static/dynamic property-name, nested-offset, and whole-property replacement sites; it does not add broader untracked-container recovery.

Shared array-offset alias writes now also run the keyed boundary, so assignment through a direct variable already bound to an object-property offset rehydrates copied runtime-cell sources before replacing that selected holder path. Object-property alias reference-cell promotion now uses the same boundary for whole-property and nested property paths, invalidating while the old source cell is still installed so root rebinding does not hide the runtime-cell source. Focused unit coverage proves copied leaf rehydration before overwrite, private-property identity matching, dirty-source equivalence, detached-path matching, direct dynamic-property overwrite, dynamic-property nested unset, dynamic-property nested reference assignment, direct dynamic compound whole-property and nested write paths, dynamic-property null-coalescing invalidation, alias-variable writes to object-property offsets, whole and nested object-property reference-cell promotion, and both static compound property write paths for the runtime-cell source.
